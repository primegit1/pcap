# PCAP Security Analyzer

A browser-based tool that reads packet captures (`.pcap` / `.pcapng`), decodes them, and reports
security findings, assets, protocols and traffic statistics.

**Everything runs locally in your browser.** Captures are never uploaded anywhere; there is no backend.

## Features

- **Formats:** pcap (microsecond/nanosecond, either byte order) and pcapng (either byte order,
  multi-section, per-interface timestamp resolution). Format is detected from magic bytes.
- **Link types:** Ethernet, Linux cooked (SLL, SLL2), raw IP / raw IPv4 / raw IPv6, BSD/OpenBSD loopback.
  Frames on other link types (e.g. 802.11) are counted and reported, not silently dropped.
- **Decoding:** Ethernet/VLAN, IPv4, IPv6, TCP, UDP, ICMP, IGMP, ARP and 40+ application protocols,
  including OT/ICS (Modbus, S7comm, DNP3, EtherNet/IP, OPC UA/DA, BACnet, Profinet, IEC 104).
- **Detection:** 100+ passive rules covering reconnaissance (port scans, sweeps, ping sweeps), DoS patterns
  (SYN/ICMP/IGMP/ARP floods), C2 beaconing, cleartext credentials and weak crypto (TLS, SSH, RDP, VNC,
  Kerberos, SNMP, databases), rogue DHCP/ARP/LLMNR/NetBIOS, DNS tunneling and DGA-like names,
  suspicious HTTP clients/downloads, exposed management services, and OT/ICS write operations.
- **Findings** carry severity, confidence, capture-time range, occurrence counts, a recommendation, and
  links to the packets that triggered them ("View packets").
- **Exports:** JSON, CSV (spreadsheet-formula safe) and a standalone HTML report.
- **Responsive UI:** parsing and analysis run in a Web Worker with progress and cancel.

## How it works

```
File ──► Web Worker ───────────────────────────────────────────────► UI
         detectCaptureFormat → parsePcap / parsePcapng
         → normalizeFrame (link types) → parsePacket (L2–L7 decode)
         → buildFlows → buildHosts → PacketIndex → ~100 rules
         → enrich (capture times, packet refs) → merge duplicates → AnalysisResult
```

- `src/parsers/` – file formats (`pcap.ts`, `pcapng.ts`), link layers (`linklayer.ts`), the capture
  pipeline (`capture.ts`), per-layer decoders, and protocol summaries under `summaries/`.
- `src/analysis/` – flows and hosts, the rule runner (`index.ts`), `findings.ts` (IDs, `createFinding`),
  `packet-index.ts`, and `security-rules/`.
- `src/workers/` – the analysis worker and its message types. Packet buffers are *transferred*, not copied.
- `src/pages/`, `src/components/` – the React UI.
- `src/test-utils/pcapBuilder.ts` – builds synthetic captures in memory for tests.

**Flows** are bidirectional. `srcIp/srcPort` is the initiator (the SYN sender for TCP) and
`dstIp/dstPort` the responder, with per-direction packet and byte counts.

## Limits and known limitations

- Single file limit 500 MB (warning above 100 MB); up to 5 files can be selected at a time. Everything is held in
  memory, so very large captures can exhaust the browser tab's memory — filter or split them first.
- Decoding is passive and stateless: there is no TCP stream reassembly, so protocol detection and
  most rules look at individual packets (a message split across segments may be missed).
- Flows are keyed by 5-tuple only (no idle-timeout splitting), so a reused port pair merges into one flow.
- pcapng Simple Packet Blocks carry no timestamp (shown as 0).
- Findings are heuristics. Use the confidence field and the linked packets to verify before acting.
